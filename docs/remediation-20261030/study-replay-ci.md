# Study bundle replay CI diagnosis

## Finding

At commit `0af61b8`, the diagnostic CI log localized the mismatch to `$[47].data_fields[0].default[0].signal[...]`, the `research-bearing` study's first generated training record. Its samples are generated by `_bearing_fixture()` in `apps/api/helioforge/engines/physical_studies.py` using `math.sin`. All 12 reported sample differences are exactly one binary64 ULP; the CI diagnostic reports additional differences were omitted. This is an OS/libm floating-point representation difference in a synthetic trigonometric fixture, not a source, dataset, or runtime identity field.

The checker now allows exactly one ULP only at `signal` samples under the `training_records` and `heldout_records` defaults of `research-bearing`. Record IDs, field names, value types, array and record counts, all other default values, and all descriptive/source metadata remain exact. Two-ULP differences and any missing/extra sample still fail. The synthetic signal arrays and other study defaults in the committed bundle remain unchanged.

Study replay now verifies that the stored inputs exactly match the frozen catalogue defaults, checks the canonical stored input digest, and passes those frozen inputs into `evaluate`. It therefore validates the committed experiment rather than regenerating platform-specific defaults before replay. Provenance/source revisions, evidence digests, result metadata and all non-input result values still receive their existing checks; the existing result comparison tolerance remains `1e-12`. Mismatch diagnostics remain bounded to 12 paths and shortened values.

Independent review identified Python's equality of positive and negative zero as an exactness gap. Integration now compares float bits and tests signed-zero changes in both frozen inputs and catalogue defaults; these changes are rejected.

## Limits

The Linux run's omitted paths have not been independently inspected; if any such value differs by more than one ULP, the checker will continue to fail with its exact mismatch path.

# Terminal major release plan

The user supplied the execution method, design direction, preservation contract and production authorization. This plan makes the integration boundaries explicit.

1. Preserve the downloaded source archive and record all twelve routes, 59 studies, 36 architectures, 24 scenarios, 36 lessons and their original handlers. Run baseline Python/frontend checks and Hallmark before inventory.
2. Replace the visual system across existing CSS with the requested Hallmark Terminal material, preserving owned DOM handlers. Do not delete routes or component trees. Add a named token sheet and a final structural stylesheet; make build composition explicit.
3. Add an independently tested Python/TypeScript reduced daily PV/battery/grid recurrence. It is synthetic, hourly and greedy; it does not replace the Python optimization or expand the study-only capability boundary. Implement linear/log two-axis sweeps, Pareto cost/shortfall comparison, local finite-difference elasticity and absolute/percentage run deltas. Document free initial/terminal energy and service comparability.
4. Integrate the new workbench at the existing Scenario compare destination beside the original comparison. Add honest diagnostics, command parsing, verified SHA-256 manifests, JSON import, CSV/Markdown reports and query-state reproduction. Keep every original command and export.
5. Verify numerical invariants and cross-language parity; test commands, corrupted imports, dirty results, all routes, accessibility and all eight requested widths. Run typecheck, lint, unit/API/browser suites and production export checks. Record actual Hallmark results, including judged gates and any open findings.
6. Bump 0.3.0 to 1.0.0 consistently. Review the complete diff against the preserved source, create a release branch/commit through GitHub Git Database APIs if local Git remains inaccessible, verify CI, merge into main, tag and deploy the exact merged revision to the existing Cloudflare Pages project. Verify public hashes, headers, assets and interactions.

Write scopes: Agent 01 owns audit records; Agent 02 owns existing styles, token/Terminal styles and font markup; Agent 03 owns new numerical modules and tests. Orchestrator owns architecture, integration, manifest/controller, release and final proof. Agent 04 will independently verify the integrated result; Agent 05 will audit release readiness. No independent agent edits the same files concurrently.

Review focus: nonfinite/unknown inputs, initial/terminal energy bias, zero percentage denominator, stale candidate exports, corrupt hash/import payloads, two-dimensional matrix limits, keyboard palette coexistence, 320px intrinsic sizing and production CSP hashes.

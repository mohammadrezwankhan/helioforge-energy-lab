# Human acceptance script — pending

No human beta sessions or assistive-technology sessions were completed in this build. Have a real evaluator use the exact packaged candidate on the intended computer and browser. Record date, candidate manifest hash, browser/OS, task outcome, time if relevant, observed confusion, screenshots and reproducible defects. Use synthetic inputs only.

## Essential tasks

1. **Start without a developer toolchain.** Extract the full ZIP, run the platform starter, observe local startup and open the printed address. Confirm the app shows API connected, new calculations work, and no provider key is requested. Verify the first-install network requirement is understood.
2. **Build an explainable comparison.** Use Quick start, save a hospital reference setup, calculate/pin it, apply the four-hour outage, calculate/pin and compare. Explain what is synthetic, what “study-only” means, and why cost alone is not enough.
3. **Change and recover inputs.** Blank a hybrid value and confirm no stale metrics remain. Correct it, then immediately click Saved setups; the click must work. Edit a storage field, navigate away/back, and verify the draft and its last-result warning.
4. **Preserve a completed case.** Calculate a 12 MWh storage case, reconnect and confirm the committed result/input is retained. Reopen a hybrid calculation from history and compare its exported input hash and stored result with the original record.
5. **Restart and recover real browser state.** Save a named hybrid setup and pin results. Reload, then close/reopen the browser at the same local address. Confirm setup and comparison recovery against the same database. Repeat in the intended browser's privacy/storage settings; a denied write must be labelled memory-only, not saved.
6. **Export, import and reset safely.** Export a named setup, alter the inputs, import the exported configuration and confirm exact values. Cancel setup deletion before confirming it. Verify the calculation still exists in API history. Back up the database before any intentional cache/database recovery experiment.
7. **Exercise failure and accessibility paths.** Stop the local server, attempt a calculation and inspect the truthful failure state. Restart/reconnect. Use only keyboard for navigation, command search, scene controls and dialogs. Test Escape/focus return, screen reader, large text/zoom and reduced motion. Inspect every required device/viewport, not just a desktop screenshot.
8. **Challenge scientific boundaries.** Try a hydrogen study-only configuration and black-start study scenario; confirm neither invents solved results. Explain hourly energy adequacy versus dynamic stability and identify uncalibrated assumptions. Report any confusing labels or suggestions of operational/investment approval.

## Acceptance record

For each task: PASS, FAIL or BLOCKED; exact expected versus actual outcome; reproduction; severity; evidence; owner; retest result. Do not combine a critical defect into an average satisfaction score. Include qualitative questions: Where were you unsure what was saved? Which result did you think was current? Could you locate assumptions and recover without help? Did motion, contrast or density impede the task?

No release approval is implied by this script. A real product/security/operations owner must accept the applicable results and outstanding risks. Native browser/storage, Windows/macOS, screen-reader and human comprehension checks are particularly important because they were not established by the container's transport/storage adapter tests.
